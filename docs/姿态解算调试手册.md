# Quadcopter 姿态解算调试手册

本版用于拆桨台架调姿态。四路 ESC 信号在 BSP 初始化后被配置为低电平 GPIO，不启动 TIM3 PWM，也不运行电机任务。保留 PPM 监测，没有解锁、混控或 PID。请先拆桨再开始操作。

## 1. 工程默认行为与改动

主控 STM32F401RE，系统时钟 84 MHz；I2C1 为 PB6/PB7、100 kHz；USART1 为 PA9/PA10、9600 8N1。蓝牙模块的 UART 波特率需要与固件相同，电脑选择蓝牙 COM 口的波特率不会改变模块配置。之前电脑记录对应 COM12，使用前重新核对设备与传出端口。

| 功能 | 本版实现 |
|---|---|
| HAL / RTOS 时基 | HAL 1 ms；μC/OS-II 10 ms，二者保持独立计数 |
| 姿态任务 | TIM4 每 5 ms 唤醒，任务优先级 7 |
| 微秒时间 | TIM2 自由运行，1 MHz；差值按 uint32 回绕处理 |
| MPU6050 | ±2g、±500°/s、DLPF=3、SMPLRT_DIV=4，14 字节数据加状态连续读取 |
| HMC5883L | 身份检查 H43、30 Hz、8 次平均、±1.3 gauss；检查 RDY/LOCK/溢出 |
| 遥测任务 | 优先级 9；UART 中断发送，持久缓冲，忙时丢帧、不积压 |
| 9600 普通模式 | 欧拉角帧 20 Hz，260 B/s |
| 9600 诊断模式 | 67 字节私有诊断帧 10 Hz，670 B/s；替代普通模式 |
| 115200 普通模式 | 欧拉角与四元数各 50 Hz，共 1400 B/s |
| MS5611 | 不初始化、不采集；后续高度模块需单独设计非阻塞状态机 |

任务只消费最新事件，过期事件合并并计数，不在超时后把旧样本连续补算。I2C 仅由姿态任务访问；采样失败和数据未就绪时，不拿旧原始值继续积分。HAL 的 BUSY 入口有额外检查，避免其内部 25 ms BUSY 等待进入正常采样路径；故障中的事务仍可能超时，因此必须看实际耗时计数。

启动时先做传感器复位和寄存器读回检查，然后约 1 秒预热、5 秒静止校准陀螺仪。检测到移动会重新累计。普通模式在校准及姿态初始化完成后才发送有效姿态，前几秒没有姿态帧是预期行为。固定帧模式不依赖传感器成功，可以先用它排查蓝牙。

## 2. 编译、配置与烧录

配置入口：`Core/Inc/flight_config.h`；标定和轴映射：`Core/Inc/sensor_calibration.h`。

Keil 打开 `MDK-ARM/hello.uvprojx`，编译器为 ARMCLANG V6，F7 编译。直接用 Keil F8 下载时，必须先把本次要用的配置写入头文件，并重新 F7。

也可在工程根目录运行命令行构建，脚本读取 Keil 实际参与构建的源文件，生成完整 AXF、HEX、MAP 和日志，不会自动烧录：

```powershell
Set-Location F:\cubemx_project\test\Quadcopter
python tools/build_firmware.py
python tools/build_firmware.py --name fixed9600 --define FLIGHT_TELEMETRY_MODE=2
python tools/build_firmware.py --name diag9600 --define FLIGHT_TELEMETRY_MODE=1
python tools/build_firmware.py --name gyro9600 --define FLIGHT_FUSION_MODE=0
python tools/build_firmware.py --name ano115200 --define FLIGHT_UART_BAUD=115200
```

编译器不在本机默认路径时，加 `--compiler-bin "实际的ARMCLANG/bin目录"`。

每个命令的产物在 `build/<name>/quadcopter.hex` 和 `.axf`。命令行 `--define` 只影响该次构建，不修改工程头文件；下载时要明确选择本次 HEX/AXF。Keil F8 不会自动改用这些输出目录，避免把旧固件误认为新固件。

| 宏 | 值 |
|---|---|
| `FLIGHT_TELEMETRY_MODE` | 0：匿名 V7；1：电脑诊断；2：固定姿态测试 |
| `FLIGHT_FUSION_MODE` | 0：纯陀螺仪；1：六轴，默认；2：请求九轴，条件不满足时用六轴 |
| `FLIGHT_BETA` | 默认 0.05；0 表示无梯度反馈 |
| `FLIGHT_UART_BAUD` | 默认 9600；115200 自动启用 50 Hz 欧拉角＋四元数 |
| `FLIGHT_FIXED_*_DEG` | 固定帧的 Roll/Pitch/Yaw，默认均为 0 |
| `FLIGHT_IMU_AXES_CONFIRMED` / `FLIGHT_MAG_AXES_CONFIRMED` | 默认 0；实际检查完成后才改 1 |

CubeMX 的 `.ioc` 已同步 TIM4 和中断优先级；应用逻辑放在独立源文件或 USER 区。重新生成后仍要检查 Keil 是否保留四个新增应用源文件，并重新编译。

## 3. 先验蓝牙与匿名协议

1. 模块上电，Windows 确认 JDY-31-SPP 已配对；默认密码通常为 1234。
2. 关闭其他串口软件，在匿名上位机 V7 选择 JDY 对应的传出 COM 口、9600 8N1。
3. 烧录固定帧模式，先看水平姿态，再单独测试 Roll=30°、Pitch=30°、Yaw=90°，每次只改变一轴。
4. 固定帧能正确显示后，才切换真实传感器模式。V5/V6/V8 协议不能混用。

协议为 `AA FF ID LEN DATA SC AC`，多字节小端。`0x03` 数据为三个 `int16(angle_deg*100)` 和一字节兼容状态值 0；`0x04` 为四个 `int16(q*10000)` 和状态值 0。实际融合状态看私有诊断标志，不能用这个固定兼容字节判断九轴是否启用。

已用实际 C 打包函数验证的固定帧：

```text
零欧拉角： AA FF 03 07 00 00 00 00 00 00 00 B3 97
单位四元数：AA FF 04 09 10 27 00 00 00 00 00 00 00 ED E4
```

要改 JDY-31 到 115200，先通过有线 UART/USB-TTL 在模块当前波特率下查询 `AT+BAUD`，再发送 `AT+BAUD8`，每条带实际 CRLF。确认成功后同步修改固件。不要把模块供电电压和 UART 逻辑电平混为一谈。

## 4. 原始数据、轴映射与零偏

先烧录诊断模式。电脑工具要求 Python、NumPy、SciPy、pyserial；可在合适的 Python 环境中安装 `tools/requirements.txt`。本机已有这些依赖，脚本兼容从普通 PowerShell 启动 Anaconda 的 DLL 搜索路径。

```powershell
python tools/capture.py --list
python tools/capture.py --port COM12 --baud 9600 --seconds 20 --output captures/check.csv
```

同时生成 `.csv` 和原始 `.bin`。该模式是二进制，普通串口助手看到乱码是正常的；不要让匿名上位机与采集工具同时占用端口。

CSV 中 ax/ay/az、gx/gy/gz、mx/my/mz 都是未标定、未旋转的原始整数。换算关系为加速度 `/16384` 得 g，角速度 `/65.5` 得 °/s，再乘 π/180 得 rad/s。陀螺仪零偏在原始传感器坐标下估计，再一起旋转到机体系。

内部机体系为右手 FLU：X 机头、Y 左、Z 上；姿态四元数按 `[w,x,y,z]` 从机体转到地理参考系，欧拉角为 ZYX。FLU 中正 Roll 为右侧下沉，正 Pitch 为机头下俯，正 Yaw 为从上向下看逆时针。不要把常见“机头上仰为正”的显示习惯直接套到传感器上。

分别设置 `CAL_IMU_TO_BODY` 和 `CAL_MAG_TO_BODY`，每一行表示对应机体轴由传感器的哪个轴组成。例如传感器 X 朝前、Y 朝右、Z 朝下，则到 FLU 的矩阵为 `{{1,0,0},{0,-1,0},{0,0,-1}}`。这只是例子，不是你们安装方向的结论。

确认步骤：

- 六面朝上时，机体对应加速度应接近正负 1g；其他分量接近 0。
- 绕每个机体正轴按右手定则转动，该轴校准后的角速度应为正。
- 磁力计按其自己的芯片轴和数据变化确认，不能默认与 MPU 同轴；HMC 读取顺序 X/Z/Y 已在驱动里改回 X/Y/Z。
- 只有旋转矩阵正交且行列式为 +1 才接受。把单独一个轴取反通常会变成左手系，程序会报配置错误。
- 完成检查后再把两个 `AXES_CONFIRMED` 改为 1。默认单位矩阵仅供初步传感器坐标调试。

显示方向通过 `FLIGHT_DISPLAY_BASIS_Q` 独立变换：`q_display = r*q*conjugate(r)`，欧拉角和四元数共用这个结果。默认 r 是单位四元数；若明确需要同时变换 FLU/NWU 到 FRD/NED 表示，可用绕 X 180° 的 `{0,1,0,0}`，此时 Pitch、Yaw 符号反转。先用固定姿态帧验证目标上位机，不能通过改六轴原始符号来迁就 3D 模型。

## 5. 六面标定与六轴融合

加速度六面标定按传感器原生 X+/X−、Y+/Y−、Z+/Z− 依次朝上，每面静止采集约 5 秒，保存为 `captures/faces/px.csv`、`nx.csv`、`py.csv`、`ny.csv`、`pz.csv`、`nz.csv`。每面至少 30 个不同采样序号；工具拒绝明显移动、错面、比例异常和交叉轴残差过大的数据。

```powershell
# 每换一面，修改 output 的文件名后执行；此处示例为 X+ 朝上。
python tools/capture.py --port COM12 --seconds 5 --output captures/faces/px.csv
python tools/calibrate.py accel --faces captures/faces
Copy-Item -LiteralPath build/calibration/sensor_calibration.h -Destination Core/Inc/sensor_calibration.h
```

把六个文件采全后才运行拟合命令。生成器保留另一种传感器的参数及两个轴映射，不会重新填成单位矩阵。

先用 `FLIGHT_FUSION_MODE=0` 检查纯陀螺仪积分：开机静止等校准完成，然后绕单轴转约 90°。若倍率、轴向错误，先改单位、量程或映射。长期漂移在此模式下是正常的。

再切回六轴，β 从 0.05 开始：平放、Roll/Pitch 各 ±30°、保持静止、回到水平。建议先在 0.02–0.10 内比较增益，每次只改一个因素。β 大时重力修正更快，也更容易把振动/线加速度带入姿态。算法在加速度模长超出 0.85–1.15g 时暂停反馈；这个门限不能排除所有线加速度，也不能替代安装和标定。

本版每次更新保护四元数和梯度归一化；无效输入、非正 dt、超过 20 ms 的时间间隔不会修改最后有效四元数。长间隔后的时间基准从新样本重建，后续继续融合，但丢失期间的实际运动不能凭空重建，必须记录故障。

六轴 Yaw 是相对航向，不会因 Roll/Pitch 稳定就变成绝对航向。±180° 处欧拉角折返和接近俯仰 ±90° 时的欧拉角奇异性也不等于四元数故障。

## 6. 磁场校准与九轴启用

1. 固定实际安装位置及供电状态，远离磁铁、钢桌等强干扰源；保持电机不转。
2. 烧录诊断模式，绕三个轴缓慢翻转，覆盖整个球面，不只水平画圈；采集约两分钟，必要时延长至三分钟。
3. 工具按磁场序号去重，使用驱动有效读取后发布、未过期的原始磁场，至少 1000 个样本、300 个不同原始向量。不会用旧校准参数造成的融合拒绝来剔除重新校准的数据，避免循环依赖。

```powershell
python tools/capture.py --port COM12 --seconds 150 --output captures/mag.csv
python tools/calibrate.py mag --input captures/mag.csv
Copy-Item -LiteralPath build/calibration/sensor_calibration.h -Destination Core/Inc/sensor_calibration.h
```

输出质量包含相对模长残差、内点比例和八个八分空间的覆盖数。要求内点比例至少 90%、内点 RMS 不超过 5%、每个八分空间至少 20 个点；秩不足、条件数异常、未收敛会拒绝导出。输出对称正定软铁矩阵，避免把椭球拟合中的任意旋转错误带入航向。

导出的是原始磁场计数的偏置和归一化矩阵：`m_body = R_mag_to_body * M * (m_raw-bias)`。偏置、软铁修正先在磁力计原生坐标做，再转到机体。软铁椭球拟合本身不能确定磁力计与机体之间的旋转，所以轴映射确认仍是必需步骤。

将 `FLIGHT_FUSION_MODE` 改为 2、确认两个轴标志为 1，并保留生成的 `CAL_MAG_VALID=1`，重新编译烧录。请求九轴但任一条件未满足，仍会使用六轴，检查诊断的 `STATUS_MAG_USED`，不能只看配置宏。

九轴只使用 100 ms 内的最近有效磁场；磁场模长偏离拟合参考 0.75–1.25 范围、通信错误或溢出时回到六轴，恢复后沿用当前四元数继续融合。磁场方向被干扰但模长仍正常时仍可能产生错误航向，当前门限不能保证识别所有磁干扰。

默认参考磁北，不包含磁偏角修正。测试水平转向 ±90°，再在不同 Roll/Pitch 下保持同一机头方向，检查倾斜是否造成虚假的 Yaw 变化。若芯片不是明确识别的 HMC5883L H43，程序会报告不支持并保留六轴；不要把 QMC5883L 当 HMC 的寄存器直接使用。

## 7. 如何验收周期和查故障

SystemView 保留 DWT 时间戳。TIM4、TIM2、USART1 中断优先级分别为 5、6、7，均在内核 BASEPRI=4 保护范围；ISR 入口对 OSIntEnter 做短临界保护，退出后才允许调度。RTOS 移植保留原来的硬浮点上下文路径和 8 字节栈对齐，异常栈增加到 512 个字；仍需实机检查抢占时浮点数据和栈余量。

RTT 通道 0 每两秒输出汇总，不占用蓝牙 UART：

```text
seq=... flags=... cal=1000 dt=当前/最小/最大 us exec=当前 max=最大 miss=... err=...
periodok=带内周期数/全部周期数 overrun=... dtbad=... filterbad=... txdrop=... stack=空闲字数/空闲字数
```

连续运行 10 分钟并保存 RTT/SystemView 记录：

- `seq` 每两秒应约增加 400；`periodok` 建议至少 99% 在 4500–5500 μs；用统计判断真实周期，不能只看定时器配置。
- `exec max` 应小于 5000 μs，`miss/err/overrun/dtbad/filterbad` 正常运行中不增长。
- 两个任务各 768 个 32 位栈字；空闲余量建议至少 25%。异常栈也需通过调试器观察。
- 诊断 CSV 只有 10 Hz，它记录抽取到的 dt，不能代替全部 200 Hz 样本的周期分布；完整分布看 RTT 累计计数和 SystemView。
- 水平 Roll/Pitch 初始目标约 ±2°；±30° 动作误差约 ±3°；磁场条件良好时航向重复性目标约 5°。使用量角工具或已知姿态夹具测量，不凭肉眼确认精度。

私有诊断 ID 为 `0xF1`，载荷 61 字节、版本 1，所有偏移定义在 `Core/Inc/telemetry_schema.h`，电脑解析器直接读取该头文件。q 缩放 10000；dt/exec 为饱和 uint16；超时总计、I2C 错误、采样和磁场序号为 uint32；详细状态位也在同一头文件。

| 现象 | 优先检查 |
|---|---|
| 普通模式无数据 | 开机是否静止至少约 6 秒；改固定帧检查 COM、波特率、蓝牙供电 |
| 固定帧也无显示 | 是否 V7、13/15 字节格式、帧头/长度/双校验；是否烧录了本次产物 |
| 诊断模式无 CSV 帧 | 是否误烧普通模式；是否占用其他 COM；是否模块 UART 波特率不匹配 |
| `CAL_SAMPLES` 经常归零 | 校准期间移动、振动，或加速度模长异常 |
| 一转就扩大几十倍 | deg/s 与 rad/s、±500°/s 对应 65.5 的比例 |
| Roll 动作影响 Pitch | 轴映射、实际机头方向、显示变换 |
| 静止 Roll/Pitch 偏差 | 六面标定、安装倾斜、参考面不水平 |
| Yaw 缓慢漂移 | 当前是否六轴，MAG_USED 是否置位 |
| 九轴 Yaw 随倾斜变化 | MPU/磁力计相对轴映射、软铁校准、磁干扰 |
| 蓝牙开启后卡顿 | exec/miss/txdrop、是否混入阻塞打印、是否发送超带宽 |
| CONFIG_ERROR | 映射非正交/左手系、校准值非有限数、软铁矩阵非正定 |
| IMU_ERROR 或 MAG_PRESENT 缺失 | 供电、共地、I2C 上拉/地址、芯片身份；修复后重启进行初始化 |
| 多任务下出现 NaN/HardFault | 任务和异常栈、内核浮点保存恢复、中断优先级、RTT/SystemView 配置 |

离线回放和软件测试：

```powershell
python tools/capture.py --replay captures/mag.bin --output captures/replayed.csv
python tools/run_tests.py
```

本机测试使用 MinGW 编译实际 C 源码；其他电脑可设置 `QUADCOPTER_HOST_CC` 为 gcc 路径。测试涵盖 C 算法旋转与收敛、无效输入、驱动寄存器配置与读回失败、实际 C 帧与 Python 解码一致性、校准拟合及退化数据拒绝。

## 8. 已验证与仍待实测

已完成电脑端自动测试与 ARMCLANG 完整编译链接，具体结果见同目录软件验证记录。未连接机架进行烧录、未采集你们的真实校准参数、未验证机体安装方向、蓝牙实际吞吐和 200 Hz 实机抖动，也未进行电机或飞行测试。上述台架验收要由实际数据确认。

后续恢复电机闭环时，需要另做解锁、遥控失联检测、传感器失效处理和混控，不应直接恢复原来的四路油门直通。

算法参考：Madgwick 的原始 IMU/AHRS 梯度下降方法，参见 [x-io 原始方法与资料](https://x-io.co.uk/open-source-imu-and-ahrs-algorithms/)。本工程将梯度写成向量残差与雅可比形式，显式传入 dt，并加入本项目的有效性判断。
